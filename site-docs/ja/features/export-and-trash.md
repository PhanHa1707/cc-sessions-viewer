# エクスポートとゴミ箱

`⌘E` は現在の会話を直接 Markdown に書き出します（Windows/Linux は `Ctrl+E`）。HTML／JSON は会話のエクスポートメニューから選びます。ローカルファイルを作成する操作で、自動公開ではありません。削除は別操作として復元可能なゴミ箱に保存します。共有前に機密情報を確認してください。

## エクスポート

![HTML として書き出したセッションをブラウザで開いたところ](/screenshots/export.png)

メニューには 3 形式があります。`⌘E` は Markdown のショートカットで、形式選択ではありません：

| 形式 | 用途 |
| --- | --- |
| Markdown | issue や PR、ドキュメントへの貼り付け |
| HTML | インラインのスタイルでブラウザ閲覧。画像の可搬性は参照元に依存 |
| JSON | 通常は解析メッセージとメタデータ。Pi は以下のネイティブエントリーツリー形式です。元ファイルのバイト単位バックアップではありません |

### Pi JSON は何が違いますか {#pi-json}

Pi の JSON メニューと一括保存は、通常の解析メッセージではなく、ビューア固有の `cc-session-viewer-pi-export` エンベロープを使います。`header`、記録済み全分岐の有効な ID 付きネイティブ `entries`、`selectedLeafId` を含みます。Markdown／HTML は選択した会話の系列を表示します。

保存するのはエントリーのオブジェクトであり、元 JSONL のバイト列ではありません。不正な JSON 行や認識できる ID のない行は省かれます。外部メディアは同梱せず、Pi CLI がこの JSON を直接取り込めることも認証していません。完全な保存には元記録とリソースを残します。2026-10-06 に [Pi の保存処理](https://github.com/jerrywu001/cc-sessions-viewer/blob/69e0b4f/src-tauri/src/agents/pi.rs)、[単体・一括処理](https://github.com/jerrywu001/cc-sessions-viewer/blob/69e0b4f/src/App.vue)、[ファイル書き込み](https://github.com/jerrywu001/cc-sessions-viewer/blob/69e0b4f/src/export.ts)で確認しました。実際の CLI 往復テストではありません。

### すべての画像をオフラインで読めますか {#offline-images}

スタイルと読み取り可能なローカル画像を埋め込み、ライト／ダークを選べます。埋め込んだ本文、スタイル、画像にサーバーは不要です。ただし `http(s)` 画像は外部参照のまま、開くと通信する場合があり、自動ダウンロードしません。ローカル画像を読み取れない場合（欠落・権限不足）は元のパスが残り、別の PC で表示できないことがあります。Markdown と解析済み JSON にも同じ画像埋め込みの制限があります。

共有前に結果を確認し、必要な原本を保管します。すべての画像の可搬性や外部リンクの有効期限を保証するものではありません。

一括エクスポートは選択したセッションに対して同じことを行い、過去のエクスポートは履歴として残るので、先週作ったファイルも見つけられます。

## ゴミ箱

![複数のエージェントから削除したセッションが並ぶ共有ゴミ箱](/screenshots/trash.png)

ファイル型はゴミ箱ディレクトリへ移動します。opencode は復元用スナップショットを保存してから選択した行を DB から削除します。明示的なデータ変更であり、読み取り専用の閲覧ではありません。

`⌘⇧T` でゴミ箱を開きます。各項目にはどのエージェント・どのプロジェクトのものか、いつ削除したかが表示され、復元すると元の場所に戻ります。復元先に同じセッションがすでに存在する場合、上書きはせず拒否します。

### 7 つのエージェントでゴミ箱はひとつ

7 つのエージェントのセッションの形はそれぞれ異なります。単一ファイルのもの、ディレクトリまるごとのもの、そして opencode は [SQLite データベース](/ja/agents/opencode)の 1 行です。ゴミ箱はこれらを同じ一覧で扱い、各項目の元のパス・エージェント・プロジェクト・保存形式を記録することで正しく戻せるようにしています。

これが最も効いてくるのがディレクトリ型のエージェントです。[Grok Build](/ja/agents/grok-build) のセッションを削除するとは、`updates.jsonl`、`summary.json`、ロックファイルを含むフォルダごと移動することであり、復元とはそのフォルダをそのまま作り直すことです。

## ここでいう読み取り専用とは {#the-read-only-guarantee}

履歴の閲覧・検索・エクスポート・分析は元の記録を書き換えません。出力ファイル、キャッシュ、設定はローカルに書く場合があります。JSON は解析済みの表現なので、完全なバックアップにはネイティブファイルを保存してください。

リネーム、ゴミ箱、復元、ターミナル／チャット続行、プロジェクト編集、ツール設定は別の書き込み操作です。ゴミ箱の完全削除は保持データを削除します。オンラインの続行は設定先へプロンプトやコンテキストを送る場合があり、更新・価格・利用枠の確認も通信します。

詳細は[プライバシーとデータの扱い](/ja/guide/privacy)、続行は[再開コマンド](/ja/agents/#resume-commands)を参照してください。
