# セッションの再開と継続

対応する CLI をインストールし、プロジェクトのディレクトリでアプリのターミナルから再開します。Claude Code と Codex は内蔵チャットにも対応し、残りの 5 つはターミナルを使います。[エージェント別コマンド](/ja/agents/#resume-commands)を参照してください。

再開は読み取り専用の再現ではなく CLI の起動です。履歴の追記、設定先への通信、許可されたツールの実行が発生し得ます。機密情報を扱う前に[プライバシー](/ja/guide/privacy)を確認してください。

![内蔵ターミナルで再開したセッション。元の記録の隣のタブに開いている](/screenshots/session-resume.png)

## どこで開き直せるか

### 内蔵ターミナルで

アプリ内の本物の PTY が、さっきまで読んでいた記録の隣のタブに開きます。ウィンドウを切り替える必要はなく、再開したセッションとその元になった履歴が並びます。

### 自分のターミナルで

Terminal.app、iTerm2、Ghostty、Warp、cmux。アプリがプロジェクトディレクトリへ移動し、`claude --resume` や `codex resume` のようなそのエージェント自身の再開コマンドを実行するので、CLI を直接使ったのとまったく同じ場所に着きます。

cmux だけ少し扱いが異なります。セッションは作業ディレクトリでワークスペースに対応づけられるため、再開は既存のワークスペースを再利用し、新しいものが積み上がりません。

## あるいはアプリ内で続ける

![Claude Code のセッションを続けるアプリ内チャット。入力欄にモデルと権限モードの切り替えがある](/screenshots/chat-preview.png)

Claude Code と Codex のセッションはアプリ内のチャットで続けられます。通常なら別のフラグで CLI を起動し直す必要がある設定が、ここではその場で変えられます：

- モデル。セッションの途中でも切り替えられます
- 推論の強さ。Opus の Ultracode を含みます
- 権限モード。エージェントが許可を求めたときのチャット内の許可／拒否ダイアログを含みます

`@` でファイルに言及し、画像を添付でき、Mermaid 図や表は書きながら描画されます。スラッシュコマンドも使え、`/fork` は元に触れずにセッションをコピーへ分岐します。

モデルピッカーは利用可能なモデルと provider 設定に従います。Codex のカスタム provider では、global `config.toml` に設定した実際の ID をモデル一覧に表示します。新規・再開チャットでは設定済みのモデルと推論 effort を既定値として使用し、ピッカーで明示した選択が優先されます。

残り 5 つのエージェントは履歴・再開・エクスポート・分析に対応しますが、アプリ内チャットは含みません。

## 現在の場所を保ったままセッションを切り替える

詳細ビューのセッションナビゲーターから別のセッションを検索して切り替えられます。バックグラウンドで開くと、新しいタブに追加しつつ現在のビューを前面に保てます。「戻る」を押しても実行中のアプリ内チャットは停止しません。再び開けば続きから戻り、明示的にチャットを閉じた場合に停止します。

## シェルタブ

通常のシェルタブはプロジェクトの作業ディレクトリで agent の隣に開きます。タイトルやディレクトリなどのメタデータを保存し、実際にアプリを再起動した後は新しいシェルを起動します。以前のプロセス、出力、実行中の `npm run dev` は復元しません。動作中にウィンドウを隠す／再表示することとは別です。

## 起動引数

エージェントごとに独自の CLI フラグを設定でき、新規・再開の両方に適用されます。典型例は `--dangerously-skip-permissions` です。エージェント単位の設定なので、ある CLI 向けのフラグが別の CLI に漏れることはありません。
